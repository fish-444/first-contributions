# AI 패션 스타일리스트

## 앱의 목적

사용자가 등록한 옷장 안에서, 오늘의 날씨·외출 목적·무드·체형에 맞는 **한 벌**을 제안한다.

예: "7~20°, 데이트, 클래식, 키작음" → 트렌치코트 + 옥스퍼드 셔츠 + 슬랙스 + 첼시부츠
    (+ 왜 그런지 이유, + 스타일링 팁, + 일교차 대응)

기획 배경과 로드맵은 `PROPOSAL.md`, 기능 상세는 `README.md`.

## 핵심 개념

"옷은 있는데 입을 옷이 없다"는 취향이 아니라 **결정 비용**의 문제다.
20벌이면 조합이 수천 가지고, 사람은 기온·목적·인상·체형·색을 동시에 못 맞춰
결정을 회피한다. 이 앱은 그 조합 공간을 8개 후보로 좁힌다.

따라서 **가진 옷으로만** 제안한다. 쇼핑 추천이 아니다.

## 추천 규칙 (근거가 있는 값 — 임의로 바꾸지 마라)

점수 항목 11개는 `README.md`의 "점수 구성" 표를 따른다. 아래 두 가지는 **출처가 있는 값**이라
"더 나은 것 같아서" 바꾸면 안 된다. 바꾸려면 근거를 함께 문서에 남겨라.

### 기온 밴드 8구간

국내에서 통용되는 **기온별 옷차림 표**를 그대로 옮긴 것이다.

| 기온 | 밴드 | 통용 표의 옷차림 | 보온 필요량 |
|---|---|---|---|
| 28°↑ | 매우 더움 | 민소매·반팔 | 1 |
| 23~27° | 더움 | 반팔·얇은 셔츠 | 1 |
| 20~22° | 따뜻함 | 얇은 가디건·긴팔 | 2 |
| 17~19° | 선선함 | 얇은 니트·맨투맨 | 2 |
| 12~16° | 쌀쌀함 | 자켓·가디건 | 3 |
| 9~11° | 추움 | 트렌치코트 | 4 |
| 5~8° | 많이 추움 | 코트·가죽자켓 | 5 |
| 4°↓ | 매우 추움 | 패딩 | 6 |

상의 두께는 **낮 최고**, 아우터·보온량은 **아침·저녁 최저** 기준이다.
일교차 8° 이상이면 상의는 낮 기온을 따르고 총보온량 구속을 낮춘다.
이걸 되돌리면 최저 기온에 끌려 낮에 더운 옷이 뽑힌다.

### 색 조화 각도

**배색 이론**의 표준 유형에 대응한다. 25° = 유사색, 150° = 보색·분할보색.

| 조합 | 점수 |
|---|---|
| 무채끼리 / 무채+포인트 1개 / 유사색(25° 이내) | +2 |
| 보색·분할보색 (150° 이상) | +1 |
| 40~80° (어느 효과도 아님) | 0 |
| 그 외 유채색 충돌 | −3 |

사진이 있는 옷은 색상 이름 대신 **사진에서 뽑은 실제 RGB**를 HSL로 바꿔 판정한다.

## 데이터

전량 브라우저 `localStorage`. 키는 `stylist.closet.v1` 하나.

```js
{
  closet: [{ id, cat, name, color, warm, fit, form, moods[], img?, rgb? }],
  nextId,
  wearLog: [{ date:'YYYY-MM-DD', ids:[] }],      // 최근 200건
  prefs:   { itemId: -3..3 },                     // 👍/👎 누적
  profile: { bodies[], height, weight, purpose, mood },
  styleLog:[{ t, a:'wear|like|dislike', b, p, m, it:[{c,f,mo}] }]  // 최근 300건
}
```

- `cat` — `아우터` `상의` `하의` `신발` `악세서리` (5종)
- `warm` 1~3, `form` 1~3, `fit` 9종, `moods` 7종 (`README.md` 표 참고)
- `img` — 긴 변 256px JPEG data URL. 원본을 넣으면 5MB 한도를 금방 넘긴다
- `rgb` — 사진에서 추출한 대표 색. 색 조화 정밀도를 올린다

## 절대 원칙

1. **사용자 데이터는 기기 밖으로 나가지 않는다.** 서버가 없는 것이 이 앱의 설계다.
   사진·옷장·위치·로그를 어디로도 전송하는 코드를 넣지 마라.
2. **API 키를 커밋하지 마라.** `.naver_keys.json` 은 `.gitignore` 에 있다.
   `proxy.py` docstring 에 키를 적어도 적용되지 않는다(설명 텍스트일 뿐).
   키를 읽는 곳은 환경변수와 그 파일뿐이다.
3. **키·프록시 없이도 앱은 완전히 동작해야 한다.** 네이버 검색은 선택 기능이다.
   `file://` 로 열었을 때 추천·옷장·사진·카드가 모두 정상이어야 한다.
4. **다운로드 파일명은 ASCII 로 만들어라.** 크로미움은 `download` 속성에 한글이 들어가면
   이름을 통째로 버리고 확장자 없는 `download` 로 저장한다(확인함).
5. **손으로 쓴 JSON 도 받아들여야 한다.** 가져오기는 `normalizeItem()` 을 반드시 거친다.
   `moods` 나 `warm` 이 빠진 항목이 그대로 들어가면 추천 단계에서 터진다.
   `cat` 과 `name` 만 있으면 통과시키고 나머지는 기본값으로 채운다.
6. **탐색 상한을 숨기지 마라.** 조합 120개·슬롯당 6개·신발 상위 3개 같은 상한이 걸리면
   콘솔에 잘린 개수를 남기고 `README.md` 에 명시한다. 상한 때문에 이론상 최적 조합이
   빠질 수 있다는 사실을 문서에서 지우지 마라.
7. **학습이 규칙을 압도하지 못하게 하라.** 로그 학습은 아이템당 ±1.2 상한이다.
   상한을 풀면 로그 몇 건만으로 기온·목적 판단이 뒤집힌다(측정: 2.05).
   로그 3건 미만이면 학습을 적용하지 않는다(콜드 스타트).
8. **추천 근거를 숨기지 마라.** 점수 구성(색 조화, 최근 착용 −3.5, 로그 학습 +1.4)을
   화면에 표시한다. 블랙박스가 되면 사용자가 교정할 수 없다.
9. **없는 것을 지어내지 마라.** 실제 상품 사진이나 패션 일러스트를 생성하는 앱이 아니다.
   등록된 색·핏·종류로 도식을 그릴 뿐이라는 한계를 문서에서 지우지 마라.

## 기술 스택

- **단일 HTML + 바닐라 JS.** 빌드 도구·프레임워크·외부 라이브러리 없음.
  `index.html` 하나에 HTML·CSS·JS가 전부 들어 있다. 이 구조를 깨지 마라.
- 그래픽은 전부 캔버스/SVG 직접 그리기. 차트·아이콘 라이브러리를 추가하지 마라.
- 라이트/다크 테마 자동 대응. 단 **코디 카드 PNG는 공유용이라 항상 밝은 카드**로 고정한다.
- `proxy.py` 는 파이썬 **표준 라이브러리만** 쓴다. `pip install` 이 필요해지면 안 된다.

## 변경 후 반드시 검증하라

이 앱은 테스트 러너가 없다. 헤드리스 크로미움으로 직접 확인한다.

```bash
# 브라우저 (컨테이너에 사전 설치됨)
/opt/pw-browsers/chromium-1194/chrome-linux/chrome

# 최소 확인 항목
# 1. file:// 로 열었을 때 JS 에러 0건
# 2. 기온·목적·무드·체형을 바꿨을 때 추천이 실제로 달라지는가
# 3. 100벌 옷장에서 recommend() 가 200ms 이내인가 (현재 약 100ms)
# 4. 8개 후보의 상·하의·아우터가 서로 다른가
# 5. 백업 내보내기 → 전체 비우기 → 가져오기로 원상복구되는가
# 6. 새로고침 후 옷장·사진·이력·취향·체형이 유지되는가
```

성능이 느려지면 원인은 대개 `recommend()` 의 조합 폭발이다.
신발·악세서리를 조합마다 풀스코어로 돌리면 100벌에서 44만 회가 되어 1초 넘게 멈춘다.
`shoeScore`/`accScore` 분리와 2단계 탐색을 되돌리지 마라.
