# [별첨] 알고리즘 분석데이터 — 첨부물 구성 지침

> 제안서 6항 「[첨부] 알고리즘 분석데이터(raw data), 관련 사진, 기술 또는
> 모델 소개 영상 자료」에 넣을 것과 **넣으면 안 되는 것**.
> 용량 제한이 없다는 점이 오히려 위험하다 — 통째로 압축하면 넘기면 안 되는
> 저작물이 함께 들어간다.

---

## 0. 왜 골라 담아야 하는가

**붙임 5(홍보 활용 동의서)로 제안서의 저작재산권이 축산물품질평가원에
이전된다.** 복제권·배포권·2차적저작물작성권이 포함된다. 따라서 첨부에 남의
저작물이 섞이면 **넘길 권리가 없는 것을 넘기는 것**이 된다.

그리고 공고문(붙임 7)은 이렇게 못 박는다:

> 출처 미기재 또는 오류/허위 기재일 경우, 서면심사 시 탈락할 수 있음

## 1. 🔴 넣지 않는다

| 제외 대상 | 이유 |
|---|---|
| **외부 농장 영상 15클립 및 추출 프레임** | 제3자 저작물. 분석 사용 허락과 배포·권리이전은 별개다 |
| **화면 5종** — `behavior_gallery` · `posture_gallery` · `detection_viewer` · `estrus_timeline` · `activity_analysis` | 생성기가 **Edinburgh(CC BY-NC)·AI Hub 프레임을 base64 로 임베드**한다. HTML 한 장이 곧 원자료 재배포다 |
| **AI Hub 원자료** (71471 · 622 · 71763) | 이용약관. 집계·산출 결과만 싣는다 |
| **Kaggle 원자료** (Edinburgh · posture · detection) | 라이선스. Edinburgh 는 **CC BY-NC** 로 비영리 조건이 붙어 있다 |
| **농장 식별자가 든 원자료 스프레드시트(xlsx)** | 농장명·소재가 식별자다 |
| **모델 가중치** `*.pt` · `*.pth` · `*.onnx` | 용량 문제가 아니라 출처·라이선스 확인 전에는 배포하지 않는다 |
| **키 파일** `.aihub_key` · `.env` · `*.key` | 압축 직전 반드시 재확인 |

### 압축은 반드시 `git archive` 로

폴더를 그냥 zip 하면 로컬에 남은 원자료·프레임·키가 딸려 들어간다.
`.gitignore` 가 위 항목을 이미 거르므로 다음이 안전하다.

```bash
git archive --format=zip -o 첨부_소스.zip HEAD:competition
```

## 2. 넣는다 — 값어치 순

### ① 대시보드 (저작권 안전한 20뷰) — 첨부의 주력

외부 연결 0 의 자체완결 HTML 이라 **압축을 풀고 `index.html` 을 더블클릭하면
바로 열린다.** 서버도 인터넷도 필요 없다. 「AI 프로그램 구현 여부」(5점)와
「업무 활용 가능 여부 및 상용화 가능성」(15점)의 가장 직접적인 증거다.

```bash
bash competition/build_all.sh
# 생성 후 1절의 화면 5종을 삭제하고 나서 압축
```

### ② 산출 데이터 — 「raw data」 항목에 정확히 대응

전부 집계값이라 농장 식별자가 없다. 제안서 표의 숫자를 심사위원이 파일에서
직접 찾아볼 수 있다.

**`data/` JSON 15종**
`korean_farm_stats` · `farm_panel` · `farm_monthly` · `farm_monthly_panel` ·
`farm_monthly_model` · `psy_priority` · `path_predict` · `path_power` ·
`posture_cnn` · `posture_crossview` · `polygon_shape_eval` · `behavior_seq` ·
`behavior_vocab` · `env_anomaly` · `estrus_label_audit`

**`outputs/` CSV 12종**
`71763_baseline_z` · `71763_centers` · `correlation` · `eda_summary` ·
`env_alerts` · `mortality_group_means` · `importance_*` 6종

부정 결과의 증거물 셋을 특히 눈에 띄게 둔다 —
`estrus_label_audit.json`(라벨 감사) · `polygon_shape_eval.json`(폴리곤 −0.018) ·
`posture_crossview.json`(교차-뷰).

### ③ 소스 코드 — 모듈 84 · 화면 빌더 27 · 서버 · 테스트

전체가 8MB 아래다. 「적용 모델 개수」와 「실증 가능성」을 문장으로 주장하는
것보다 실행 가능한 코드가 낫다.

### ④ 검증 로그 — 「알고리즘 테스트 여부」(10점) 직결

터미널 출력을 **텍스트 파일로 떠서** 넣는다. "테스트했습니다"가 아니라
실행 결과를 제출하는 것이 된다.

```bash
python competition/tests/smoke_test.py  > 04_검증로그/smoke_test.txt   # 103/103
python competition/tools/check_docs.py  > 04_검증로그/check_docs.txt   # 불일치 0
```

### ⑤ 사전등록 + git 로그 — 가장 반박하기 어려운 증거

커밋 타임스탬프가 **적중 정의를 결과 보기 전에 적었음**을 증명한다.

```
등록 2-A 커밋      2026-08-27   (3177470 "등록 2-A 적중 정의 — 라벨 확인 전 보완")
등록 4  커밋      2026-08-24   (670a325 "행동 어휘 축소 규약을 숫자 보기 전에 커밋한다")
외부 영상 측정      2026-08-28 ~ 29
```

```bash
git log --date=iso --format='%ad %h %s' -- competition/docs/PREREGISTRATION.md \
  > 04_검증로그/git_log_prereg.txt
```

`PREREGISTRATION.md` 와 이 로그를 함께 넣는다.

### ⑥ 문서

`CAPABILITIES.md`(할 수 있는 것 / 없는 것) · `PREREGISTRATION.md` ·
`EXTERNAL_EVAL.md`(외부 영상 관통 — 한계 포함) · `MANUAL.md`(모듈 색인) ·
`STATUS.md`(현황·구멍).

### ⑦ 「관련 사진」

**농장 화이트보드 사진 ↔ `breeding_board.html` 캡처를 한 장에 나란히.**
제안서 본문의 *"양돈장은 이미 표를 쓰고 있다. 그래서 출력 표를 그대로 출력
스키마로 삼았다"* 를 사진 한 장이 증명한다.

⚠️ 사진에 농장명·소재·인물이 찍혔으면 가린다.

그 밖: 농장 등록 화면 · 실측 진단 5패널 · 번식 콘솔 조치 큐 캡처.

■ 포함하지 않은 것과 그 이유
외부 농장 영상, AI Hub 원자료, Kaggle 원자료는 저작권 및 이용약관에 따라

## 5. 「모델 소개 영상」 — 3~5분 화면 녹화

클릭만 하면 되므로 한 번에 찍힌다.

| 시각 | 화면 | 말할 것 |
|---|---|---|
| 0:00 | 농장 등록 | 돈사를 넣으면 연간 출하 상한과 **병목 돈사의 이름**이 나온다 |
| 1:00 | 실측 진단 | 466 농장-연 분포 위 내 위치 — 순위가 아니라 거리. 격차 → 두수 → 원/년 |
| 2:00 | 교배표 보드 | 현장 화이트보드 사진과 나란히 — 쓰던 서식 그대로 |
| 3:00 | 번식 콘솔 | 교배 창 · 긴급도순 조치 큐 · 작업지시서 인쇄 |
| 4:00 | **터미널** | 자동 테스트 103개와 문서-코드 수치 대조를 **눈앞에서 실행** |

마지막 구간이 핵심이다. 화면을 보여주는 영상은 흔하지만 **테스트를 실제로
돌려 보이는 영상은 드물다.**

⚠️ 녹화 중 외부 영상·원자료가 화면에 뜨지 않게 한다. 파일 탐색기·브라우저
탭·터미널 경로에 농장명이나 영상 파일명이 노출되지 않도록 한다.
