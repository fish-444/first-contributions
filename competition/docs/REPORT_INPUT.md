## 0. 한 줄 서사

> **발정을 놓치면 번식이 무너진다. 그런데 번식만 잡아도 농장은 안 산다 —
> 발정 탐지에서 출하까지 한 줄로 잇는다.**

```
   기둥 1  발정·교배 관리          기둥 2  돈사 운영 관리
   달력이 카메라를 겨냥 →          돈사 스펙 → 수용 두수·병목 이름
   행동 구성비 → 자기 기준선 →     → 연간 출하 상한 → 가는 길 셋
   의심 순위(판정 아님)            + 환경 위험 알람 + 법정·행정 검산
              ↑                              ↑
        근거층 — 국내 실측 466행 · 월별 179농장 · 공개 데이터
```

**독창성 셋** (별도 장이 없으므로 문서 전체에 녹입니다):

1. **센서를 늘리는 대신 달력이 카메라를 겨냥한다** — 이미 아는 번식 일정이
   사전확률을 공짜로 준다.
2. **절대값이 아니라 자기 기준선** — 방·돈사마다 카메라·센서가 달라 절대값
   비교가 성립하지 않는다. 문턱도 발명하지 않고 자기 이력에서 역산한다.
3. **못 하는 것을 측정해서 명시한다** — 데이터 감사 자체가 분석 결과다.

| 기능 | 사용자가 받는 답 | 등급 |
|---|---|---|

| **돈사 → 연간 출하 상한** | 상한 · 현재 · 달성률 · 상한까지 가는 길 셋 | 계산 |

| **행정 등록 검산** | 총사육수 ↔ 동별 합 ↔ 자리 수 ↔ 허가/무허가 면적 | 계산 |
| **법정 사육밀도** | 「축산법 시행령」[별표 1] 조문값 대비 과밀·초과 두수 | 지침(조문) |
| **환경 위험 알람** | 지침 위반(위험) + 자기 기준선 편차(주의). **제어 지시는 하지 않음** | 계산+지침 |

### 이 축이 지키는 성질 셋 (발표에서 강조할 지점)

- **답은 두수가 아니라 병목의 이름이다.** 돈방은 돈사를 건너뛰어 쓸 수 없어
  총량이 커도 한 곳이 막히면 거기서 끝난다. 예시 구성에서 분만틀 기준
  341두인데 **임신사 자리가 299두**라 실제 규모는 **299두**다.
- **방이 상한을 다시 깎는다.** 복당 이유두수 목표가 12두라도 자돈사 396자리에
  분만틀 36개면 **11.0두가 천장**이다.
- **막힌 돈사가 병목이다.** 회전이 안 되는 건 두수를 줄여서 풀리지 않는다.

### 생산량 항등식

    연간 출하 = 분만틀 × 채움률 × 복당 이유두수 × 육성률 × 연간 배치수

앞의 둘은 **지어 놓은 것**이라 성적으로 못 바꾼다. 그래서 상한까지 가는 길이
정확히 셋이다. **세 몫을 더하지 않는다** — 항이 곱해지므로 개별 합은 총
격차와 같지 않다.

## 1-4. 성적 진단·처방 (근거층이 직접 사용자에게 닿는 부분)

| 기능 | 사용자가 받는 답 |
|---|---|
| **분포에서 내 위치** | 순위가 아니라 **거리**(IQR 단위) |
| **격차 → PSY 회수량 → 원/년** | 지표별 되돌림 몫 |
| **하락 방어 기댓값** | 농장-연의 33%가 1두 이상 하락(중앙 −2.40두) → 연 **2,976만원** |
| **여름 손실 선별** | 전체 −2.97%p 뒤의 농장별 분포(하위10% −4.4 ~ 상위10% **+13.0%p**) |
| **처방 순서표** | 회수/방어/계절 세 축 + 근거 등급 A/B/C |
| **현재 ↔ 달성 가능 상한** | 지표별 상한(**분포 상위10%와 돈사 천장 중 작은 쪽**)과 그때의 PSY |
| **자기 낙관 폭 신고** | 프로그램 가정 PSY 27.69 vs 실측 중앙 25.34 → **+2.36두** |

## 1-5. 이 프로그램이 **하지 않는** 것 (사용자에게 미리 말하는 것)

- **개입 효과를 주장하지 않는다.** 격차의 분해까지이고, 실농장 개입 실험은
  하지 않았다.
- **항목을 합산해 "다 하면 +N두"라고 쓰지 않는다.**
- **빈 칸을 중앙값으로 채우지 않는다** — "무엇이 없어서 못 냈는지"로 답한다.
- **위법을 판정하지 않는다.** 무허가면적은 "적법화 대상일 수 있다"까지.
- **환경 제어 지시를 내리지 않는다.** 위험 알람까지.
- **군사 전환 시기를 말하지 않는다** — 별표에 부칙이 없어 확인하지 못했다.

# Ⅱ. 어떤 작업들로 이뤄졌는가

## 2-1. 개발 과정의 성격 — **자기 오류 교정의 연속**

이 프로젝트에서 가장 인용할 만한 것은 기능 목록이 아니라 **틀린 것을 스스로
찾아 고친 기록**입니다. 아래는 전부 우리가 만든 뒤 우리가 잡은 결함입니다.

| 무엇이 틀렸나 | 어떻게 드러났나 | 고친 결과 |
|---|---|---|
| 육성률 92.1% | 분위수끼리 **잘못** 나눠 계산 — 그런 농장은 실재하지 않는다 | 농장별 분포로 **93.9%** |
| 복당 이유두수 12두를 상한으로 사용 | 자돈사 수용력이 정한 천장을 무시 | 천장 **11.0두**, 허수 594두·1.4억 제거 |
| 화면이 관행 상수(회전율 2.3·WEI 5.0)를 박아 둠 | 같은 돈사가 화면 295두 vs 모듈 299두 | 상수를 모듈에서 주입, **299두**로 일치 |
| 번식주기 상수가 두 모듈에서 불일치 | 지침이 4.3% 낙관 | 농장 실적에서 추정하도록 통일 |
| 배치 시뮬레이터 "전이 0회 = 정상" | 배치가 한 발짝도 못 가면 위반 0건으로 보인다 | **무처소 검사** 신설 |
| 이상 점수가 미측정 채널까지 합산 | 평시에 z≈−7.4가 섞여 허위 질병 경보 | 구성비 부재/채널 부재를 분리, 2.62 → **0.254** |
| 번식사 법정 밀도를 "기준 없음"으로 비움 | 조문에 임신돈 1.4·분만돈 3.9가 실재 | 일곱 용도 전부 판정 — 임신사 28두 초과가 그제야 잡힘 |
| 문서 검사기가 굵은 글씨를 못 봄 | 개수를 굵게 쓰면 정규식이 `**`를 못 넘어 검사를 통과 | 강조 표시를 걷고 대조 — 숨어 있던 낡은 수치 2건 발견 |

## 2-2. 검증 방법론 — 무엇으로 "된다"고 말하는가

| 방법 | 왜 그렇게 했나 |
|---|---|
| **개체 분리 GroupKFold** | 같은 돼지가 학습·검증에 함께 들어가면 성능이 부풀려진다 |
| **뷰별 LOVO(못 본 카메라)** | 실제 농장은 학습에 없던 카메라를 쓴다 |
| **train==val 결과 불인용** | 제공 모델의 0.953은 검증이 아니다 → 홀드아웃 재측정 |
| **음성 대조군 테스트** | 반드시 잡아야 하는 입력을 일부러 주입해 검사가 우는지 본다 |
| **브라우저 교차 검증** | 화면 JS와 파이썬 모듈의 결과를 Chromium에서 직접 대조 |
| **문서-코드 자동 대조** | `check_docs`가 문서 수치를 코드 산출과 맞춘다 (불일치 0) |
| **사전등록(PREREGISTRATION)** | 결과를 보기 전에 평가 규약을 커밋한다 |
| **시드 반복** | 시드 SD 밖으로 올라야 개선으로 인정 |

## 2-3. 핵심 규율 — 문서에도 코드에도 같은 규칙

1. **계산을 재구현하지 않는다.** 서버도 화면도 모듈을 부른다. 테스트 101개가
   응답과 모듈 출력을 대조한다.
2. **상수를 화면에 박지 않는다.** 정본 모듈에서 주입한다.
3. **문턱을 발명하지 않는다.** 자기 이력의 경보율 대역(0.5~5%)에서 역산한다.
4. **근거 있는 것만 신고한다.** 행동 15종 중 AP 0.2 이상인 **4종만** 계약에
   올리고, 분만징후 헤드가 근거 부족으로 막히는 것까지가 출력이다.
5. **등급을 섞지 않는다.** 실측/계산/유도/합성/지침을 한 표에 나란히 놓지 않는다.

## 2-5. 실패를 측정한 작업 — **설계를 결정한 부정 결과**

| 측정 | 방법 | 결과 → 설계 결정 |
|---|---|---|
| 발정 직접 판정 | 카메라·개체 통제 후 검증 | AUC **0.465** → 직접 판정 포기, 달력 게이팅+기준선 구조로 |
| 폴리곤 라벨 상한 | 정답 폴리곤을 줬을 때의 상한 측정 | MF1 **−0.018** → bbox 채택, 원천 10GB·14시간 학습 회피 |
| 외음부 필드 | 값 분포·대조군 감사 | 22,497건 전부 "Y" → 필드 미사용 |
| 계절 검출력 | 검출력 분석 | 검출 한계 **18%p** vs 실측 2.97%p → 로그 기반 판정 포기 |
| 자세→발정 전파 | 개선분 전파 측정 | **+0.004**(시드 SD 0.019 안) → 자세 개선을 발정 근거로 쓰지 않음 |
| 행동에 딥러닝 | 1D-CNN vs 손피처 RF | 0.427 vs **0.485** → 요약 피처 유지 |

## 2-6. 분모 명시와 거절 옵션 — **얇은 창은 점수를 내지 않는다** `계산`

구성비만 보고 분모를 안 보면, 추적기가 거의 못 잡은 창이 평시 창과 나란히
기준선에 들어가고 그 위에서 경보가 납니다. 미측정 채널을 0으로 채워
z≈−7.4를 만들던 결함과 **같은 계열**입니다.

- `fold()` 가 구성비와 함께 **분모(`n_used`)와 커버리지**를 냅니다.
- **거절 옵션**(`min_score`)으로 확신 낮은 검출을 구성비에서 빼고 따로 셉니다.
  기본값은 없습니다 — **문턱을 지어내지 않습니다.**
- 창이 평소보다 얇으면 **점수를 내지 않고 "못 잰다"로 표기**합니다.

문턱은 방마다 **자기 이력에서 나옵니다.** 창 하나의 분모가 평소(`n_typical`,
이력 창의 중앙값)보다 얇을 때 늘어나는 표본 분산이 그 방 기준선 산포를
넘으면 못 재는 창입니다. 상수가 없습니다.

**설계에서 한 번 틀렸다가 고쳤습니다.** 처음에는 오차를 *그 창의* 구성비에서
쟀는데, 그러면 구성비가 옮겨 간 창 — 곧 신호가 있는 창 — 일수록 오차가
커져서 **진짜 이탈을 먼저 막습니다.** 시연에서 평시 두께(300개) 창까지
막히는 것을 보고 발견했고, 기준선의 중심 p에서 재도록 고쳤습니다. 지금은
게이트가 **분모만** 봅니다 — 같은 분모면 평시 창과 의심 창의 판정이 같고,
테스트가 그 성질을 고정합니다.

## 2-7. 어휘 축소 — **재학습 없이 단위를 바로잡았다** `실측`

응용(기준선 층 `HEAD_SIGNS`)이 구성비로 쓰는 어휘는 넷뿐입니다:
`Resting` · `Eating` · `Walking` · `Searching`. 제공 모델의 계약
(AP 0.2 이상 4종)도 같은 넷입니다. 그 밖의 구분에서 나는 혼동은
**의심 순위에 닿지 않습니다.**

같은 예측을 두 어휘로 채점했습니다 — 모델을 다시 학습하지 않았고 분할·
피처도 그대로입니다(개체 GroupKFold 5 · 기하+모션+롤링 20피처 RF).

| 어휘 | 종수 | 정확도 | Macro-F1 | 다수 기준선 | 여유 |
|---|---|---|---|---|---|
| 원 어휘 | 12 | 0.484 | 0.348 | 0.332 | +0.152 |
| **응용 어휘** | 5 | **0.576** | 0.622 | 0.332 | **+0.244** |

**정직하게 읽는 법**: 병합은 정확도를 구조적으로 낮출 수 없으므로 +0.092
자체는 개선의 증거가 아닙니다. 값어치는 둘입니다 — (1) 최다 클래스가 어느
어휘에서든 Searching 이라 **다수 기준선이 0.332 로 그대로**여서, 여유가
+0.152 → +0.244 로 넓어진 것은 병합이 거저 준 몫이 아닙니다. (2) 응용
어휘에서도 42%가 틀리고, **가장 큰 클래스인 Searching 이 가장 약합니다**
(재현율 0.525; Eating 0.891 · Walking 0.662 · Resting 0.641).

자세에서 본 성질(5클래스 0.557 → 응용 3클래스 0.732)이 행동에서도
재현됐지만 **폭은 절반 수준**입니다. 남은 혼동은 병합이 못 지우는 쪽
(`standing → investigating` 0.353 · `fight → walk` 0.306 — 기타에서 응용
클래스로 새는 방향)에 몰려 있습니다.

Macro-F1 +0.274 는 클래스 수가 줄며 평균의 분모가 바뀐 **기계적 몫이
섞여 있어** 정확도만큼 곧이 읽지 않습니다.

> **딥러닝이 갈린 이유는 하나입니다** — 요약 피처가 원본의 정보를 버렸는가.
> 자세는 60차원 요약이 머리 방향·질감을 버려서 CNN이 이기고, 행동은
> `speed`·`accel`·롤링 통계가 시간 정보를 이미 담아서 DL이 집니다.

## 4. 집필 규칙 — 본문에서 반드시 지킨다

1. **수치마다 등급을 붙인다.** 한 표에 실측과 합성을 섞지 않는다.
   (실측 / 계산 / 유도 / 합성 / 지침)
2. **합산하지 않는다.** 생산량 항등식은 항이 곱해지므로 "다 하면 +N두" 금지.
3. **개입 효과를 주장하지 않는다.** 격차의 **분해**까지다. 실농장 개입 실험 없음.
4. **부정 결과를 앞에 놓고, 뒤에서 철회하지 않는다.**
5. **빈 칸을 중앙값으로 채우지 않는다.**
6. **출처를 문장에 붙인다** (공고 요구사항이자 우리 규율).
7. 판정이 아니라 **의심**이라고 쓴다 — 영상 축의 출력은 "이 방을 오늘 먼저
   보라"까지다.
8. **개인정보·농장 식별자를 본문에 쓰지 않는다** (성명·연락처·농장명).
