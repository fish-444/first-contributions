### 블록 B — 데이터 확보 방안의 현실성 및 데이터 품질 (10점)

**(a) 배점 문구** — "현실적으로 사용 가능한 데이터 품질 여부, 데이터
신뢰성 등"

**(b) 지금 상태 — 여기가 가장 위험합니다.**
p5에 이렇게 적혀 있습니다:

> 외음부 주석은 개체·날짜별 양성 시점이 있어 발정 달력으로 bbox 라벨과
> 연결했다.

데이터를 아는 심사위원에게 이 문장은 **정답을 피처로 쓴 것(누수)**으로
읽힙니다. 그런데 실제로 우리가 한 일은 정반대입니다 — 감사에서 적색이 나와
**본 실험을 중단**했습니다. 지금 제안서는 우리가 잡아낸 걸 안 썼고, 대신
안 한 일을 한 것처럼 보이게 써 놓았습니다.

**(c) 쓸 재료 — 라벨 감사 실측 (`estrus_label_audit.py`)**

bbox 라벨 (1,132파일 · 7,830박스):

| 검사 | 결과 |
|---|---|
| 채널만으로 발정 분리 | **0.9995** (다수 기준선 0.5121). ch1~8 전부 Y · ch9~16 전부 N (예외 4건) |
| `INJECTION` 블록 유무만으로 분리 | 0.5903 (+0.078) — 결측이 곧 라벨 |
| 한 파일 안에서 라벨이 갈리는 비율 | **4 / 1,132 = 0.35%** → 프레임 라벨이 아니라 **돈방·세션 라벨** |

외음부 주석 (22,497건 · 175개체 · 7일):

```
필드 = { DATE · FARM_NAME · ANIMAL_ID · ESTRUS }
ESTRUS 값 분포 = {"Y": 22497}          ← N 이 하나도 없다
외음부 상태 기술 필드(발적·부종·점액·좌표) = 0개
```

즉 이 디렉터리는 **발정 개체만 모은 목록**이고, 파일의 존재 자체가 라벨입니다.
"비발정"은 그날 사진이 안 찍힌 개체로 정의될 수밖에 없습니다.

그 결과 **카메라·개체를 통제하면 발정 판정 AUC 0.465**(동전 0.5 아래)입니다.
원인은 모델이 아니라 라벨 어휘와 라벨 단위 둘 다입니다.

차선책이던 **울음소리 주석**(225파일 · `CRY_COUNT`·`CRY_TIMESTAMP`)은 피처는
실재하지만 **개체 ID가 없어 방·세션 단위**라 같은 카메라 교락에 그대로
걸립니다. 그래서 이것도 지금 데이터로는 성립하지 않습니다.

**데이터 요구사항으로 바꿔 쓴 결론 — 이 세 줄로 문단을 닫아 주세요:**

1. 같은 개체를 **발정일과 비발정일 모두** 촬영 (현재는 발정일만)
2. 외음부 **상태를 등급으로** 주석 (발적 0~3 · 부종 0~3 · 점액 유무)
3. 발정 라벨을 **카메라와 독립적으로** 부여 (현재는 방이 곧 라벨)

**병렬로 쓸 두 번째 부정 결과** — 622에서 정답 폴리곤을 써도 자세 성능이
**MF1 −0.018**로 오히려 내려갔습니다. 원천 이미지 10GB 다운로드와 14시간
CPU 학습을 하지 않아도 된다는 결론을 라벨 8MB로 냈습니다. 이건 "데이터
확보 방안의 현실성" 그 자체입니다.

**써야 할 논지** — 우리는 데이터를 받아서 성능을 낸 게 아니라, **쓰기 전에
품질을 감사했고 못 쓰는 것을 못 쓴다고 판정했다.** 그리고 그 판정을 다음
데이터 구축의 요구사항으로 환원했다. p5의 기존 문장은 이 논지로 **교체**해
주세요(추가가 아니라 교체).

**(d) 분량** — 본문 3분의 2쪽(약 600자) + 표 하나.

### 블록 C — 축산 현장문제 해결 방안 제시 (15점, 최대 배점)

**(a) 배점 문구** — "축산 현장문제 해결 방안 제시"

**(b) 지금 상태** — p15에 있고 논지는 옳습니다("인력·장비를 늘리지 않는다",
"관찰을 줄이는 게 아니라 순서를 정한다"). 다만 **금액이 하나도 없습니다.**
문제를 진술했는데 그 문제가 얼마짜리인지가 안 나옵니다.

**(c) 쓸 재료 — 금액으로 환산된 실측 (300두 기준 환산)**

| 항목 | 금액 | 근거 |
|---|---|---|
| PSY +1두의 값 | **연 3,751만원** | 항등식 분해 |
| 성적 하락 방어의 값 | **연 2,976만원** | 농장-연의 33%가 1두 이상 하락(중앙 −2.40두) |
| 여름 계절 손실 (중앙 농장) | **연 733만원** | 67농장 분포 중앙 |
| 여름 계절 손실 (상위 10% 취약 농장) | **연 3,172만원** | 같은 분포 p90 |
| 67농장 실제 규모 합산 | **연 9.7억원** | 농장별 실제 상시모돈 적용 |

**계절 손실의 성격** — 분만율이 여름 교배 81.1% vs 겨울 84.1% = **−2.97%p**.
분만 시점으로 보면 11월이 최저라 안 보이고, **임신 114일을 되돌려야** 7·8월이
드러납니다. 관측 분산의 **41%만 진짜 농장 차이**이고 나머지는 표본 오차인데,
걷어내도 분포는 사라지지 않습니다 — 여름에 8%p 무너지는 농장과 0%p인 농장이
같이 있습니다. 그래서 **공통 처방이 아니라 선별 처방**입니다.

**무너지는 경로** — 여름에 평균이유 −0.25두, 7일내재귀율 −0.2%p로 사양은
거의 안 움직이는데, 임신사고 구성이 **1차 재발 쪽으로 +8.0%p** 기웁니다
(겨울 33.4% → 여름 41.4%). 사양이 아니라 **착상**입니다.

**계절 취약도는 규모·성적과 무관합니다** — PSY와 ρ −0.149, 상시모돈과
ρ −0.163 (n=67). 잘하는 농장도 여름은 피하지 못합니다.

**써야 할 논지** — 현장 문제를 ① 얼마짜리인지 ② 어느 농장의 문제인지
③ 어느 달에 손대야 하는지 세 층으로 특정한다. "생산성이 낮다"가 아니라
"당신 농장의 7월 교배가 연 733만원을 깎고 있고, 그건 사양이 아니라
착상에서 새고 있다"까지 간다.

**(d) 분량** — 기존 p15 문단 유지 + 금액 문단 하나 추가(약 400자) + 표 하나.

## 3. 절대 규칙 — 어기면 제안서가 망가집니다

1. **수치를 새로 만들지 마세요.** 이 문서 4장에 없는 숫자는 쓰지 마세요.
   "약 30% 향상" 같은 추정치를 지어내면 그 자리에서 신뢰가 무너집니다.
2. **분모를 뗀 비율을 쓰지 마세요.** 모든 비율에는 n이 붙어야 합니다.
3. **등급을 섞지 마세요.** 실측·계산·유도·합성·지침을 같은 표에 나란히
   놓지 마세요. 섞어야 하면 등급 열을 만드세요.
4. **효과를 약속하지 마세요.** "PSY가 2두 오릅니다"가 아니라 "PSY 1두는
   연 3,751만원이고, 우리 시스템은 그 격차를 지표별로 분해해 어디부터
