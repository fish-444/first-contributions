# 🌿 알로카시아 스마트팜 3D 온실

사진 + 이름을 입력하면 **Roboflow(YOLO)** 가 분석하고, **3D 온실**에 화분으로 나타나요.
화분을 클릭하면 내가 정한 이름과 분석 결과(잎 개수·겹침·새순)가 뜹니다.
센서·RAG 없이 **[사진+이름 → YOLO → 3D 반영 + 이름 커스텀]** 에만 집중한 깔끔한 단일 웹앱.

> 코딩 몰라도 돼요. 아래 순서대로 따라 하시면 됩니다.

---

## 📁 폴더 구조
```
alocasia-farm/
├── main.py              ← FastAPI 백엔드 (분석·추가·제거·이름수정)
├── requirements.txt
├── README.md
└── static/
    ├── index.html       ← 3D 온실 + 업로드 폼 + 리스트 + 모달
    ├── three.min.js     ← 3D 라이브러리 (동봉)
    └── OrbitControls.js
```

## ▶️ 실행
```bash
cd 경로/first-contributions/alocasia-farm
python3 -m pip install -r requirements.txt     # 처음 한 번 (Windows: python)
python3 -m uvicorn main:app --reload           # 서버 실행
```
브라우저에서 **http://127.0.0.1:8000** 접속.

> **`Form data requires "python-multipart" to be installed`** 로 안 뜬다면
> 설치가 중간에 끊긴 겁니다. 이것만 다시 실행하세요:
> ```bash
> python3 -m pip install fastapi "uvicorn[standard]" python-multipart pillow requests
> ```
> `ultralytics`(로컬 `.pt` 전용, torch 포함 2GB)는 로보플로우·데모만 쓰면 필요 없습니다.

## 사용법
1. 왼쪽 **① 식물 이름** 입력 (예: 프라이덱)
2. **② 식물 사진** 선택
3. **③ 자리 선택** (A1~E10 중 빈 자리) → **🌱 온실에 추가**
4. 3D 온실 해당 자리에 화분이 나타나고, **자리 지도**와 **리스트**에도 반영됨
5. 화분·리스트·자리 지도 **클릭** → 분석 결과 **모달**
6. 모달에서 **이름 수정**, **화분 방향 회전**, **새 사진으로 갱신**, **제거** 가능

### ✋ 틀린 값 직접 고치기
사진이 뭉개지거나 잎이 가려지면 탐지가 틀립니다. 모달에서 바로 고칠 수 있어요.

- **크기 등급** — 소품 / 중품 / 대품 버튼을 눌러 교체
- **잎 개수** — 단계별 `−` `+` 버튼
- **단계 이동** — 성엽 `−1` + 노엽 `+1` (총 개수는 그대로)

직접 고친 식물엔 **✋ 직접 수정함** 표시가 붙습니다.
`잎 유지` 모드로 스캔하면 고친 값이 보존되고, `덮어쓰기` 모드에선 새 탐지값으로 바뀝니다.

### 🔁 스캔 모드
스캔할 때 기존 기록을 어떻게 할지 고릅니다.

| 모드 | 동작 | 언제 |
|---|---|---|
| **잎 유지 · 새 잎만 기록** (기본) | 잎 수가 **줄어드는 건 무시**하고, 늘어난 만큼만 새 잎으로 기록 | 평소 |
| 탐지값으로 덮어쓰기 | 탐지 결과 그대로 반영 | 잎을 잘라냈을 때 |
| 전부 지우고 새로 채우기 | 등록된 식물을 모두 삭제 후 재생성 | 배치를 갈아엎었을 때 |

기본이 `잎 유지`인 이유: 탑뷰에선 큰 잎에 가려 안 잡히는 잎이 매번 달라집니다.
그대로 반영하면 어제 8장이던 식물이 오늘 5장이 돼요. 그래서 **감소는 '가려짐'으로 보고 무시**하고,
**증가분만 새 잎으로 기록**합니다. 단계 분포(새순→성엽→노엽)는 탐지가 기존만큼 잡았을 때 갱신되므로
잎이 자라는 변화는 그대로 따라갑니다.

새 잎이 나면 스캔 결과에 `새 잎 2장` 으로 표시되고, 개체별로 `leaf_log` 에 최근 30건이 쌓입니다.

### 🏡 농장 전체 사진 한 장으로 스캔
탑뷰로 농장 전체를 찍어 올리면, 잎을 **식물별로 묶어** 여러 개체를 한 번에 등록합니다.
사진 속 위치가 그대로 3D 자리로 이어져요 (사진 위쪽 = 온실 안쪽 A줄).

같은 자리에 이미 식물이 있으면 **이름과 방향은 유지한 채 상태만 갱신**되므로,
매일 같은 각도로 한 장씩 찍으면 개체가 늘어나지 않고 최신 상태로 덮어씁니다.

### 📐 여러 장 + 원근 보정 (왜곡 없는 탑뷰)
비스듬히 찍히면 위치가 밀립니다. 사진마다 **선반 네 모서리를 클릭**하면 그 왜곡을 폅니다.
2~4장으로 나눠 찍으면 해상도도 올라가고, 한 선반 좌표계로 합쳐집니다.

```
📐 여러 장 + 원근 보정  →  사진 2~4장 선택
   → 사진마다 [좌상 → 우상 → 우하 → 좌하] 순서로 모서리 클릭
   → 이 사진이 덮는 구역 선택 (전체 / 왼쪽 절반 / 우상 사분면 …)
   → 자동으로 합쳐서 등록
```

#### 🎯 모서리가 안 보일 때 — 화분을 기준점으로
케이지가 좁거나 식물이 크면 **트레이 모서리가 프레임에 안 들어옵니다.**
뒤로 물러설 공간이 없으면 구조적으로 못 담아요. 이럴 땐 모서리 대신 **화분**을 씁니다.

```
1회차: 🪴 화분 자리 지정 (트레이가 그나마 보이는 사진 1장으로)
이후:  🎯 화분 기준으로 스캔 → 아무 각도로 찍고 → 아는 화분 4개 이상 클릭
       → 클릭할 때마다 배치 지도가 뜨고, 지도에서 같은 위치를 누르면 됨
```

> 자리 이름(`C3`)만으로는 어느 화분인지 알 수 없어서, 고를 때 **저장된 배치를
> 작은 지도로** 보여 줍니다. 사진에서 찍은 화분과 같은 위치를 지도에서 누르면 돼요.
> 이미 고른 화분은 회색으로 빠집니다. 같은 지도가 왼쪽 패널에도 항상 떠 있습니다.

원근 변환은 **평면 위 대응점 4쌍**만 있으면 되고, 그게 모서리일 필요가 없습니다.
오히려 화분이 프레임 안쪽에 퍼져 있으면 외삽이 아니라 **내삽**이라 더 정확해요.
화분은 항상 잘 보이고, 안 움직이고, 헷갈리지도 않습니다.

- 기준점을 4개보다 **많이** 찍으면 최소제곱으로 클릭 오차가 평균돼 정확도가 올라갑니다
- 고른 화분이 **한 줄로 서면 안 됩니다** (넓게 퍼질수록 좋음)
- 화분 자리가 4개 이상 지정돼 있어야 버튼이 나타납니다

#### 사진을 '이어 붙이지' 않습니다
스티칭(픽셀 합성)은 이 문제에 맞지 않습니다.

| 스티칭의 문제 | |
|---|---|
| 왜곡이 안 사라짐 | 합치기는 겹친 사진을 잇는 것일 뿐, 입력이 기울어져 있으면 결과도 기울어짐 |
| 특징점 매칭 실패 | 비슷한 초록 잎이 반복되는 캐노피에서 오매칭 |
| 유령/어긋남 | 정지된 장면을 전제하는데, 잎은 촬영 사이에 움직임 |
| 무거움 | OpenCV 60MB 의존성 |

그래서 **픽셀이 아니라 결과를 합칩니다.** 사진마다 네 모서리로 원근 변환(호모그래피)을
구해 **탐지된 좌표만** 선반 좌표계로 옮기고, 겹치는 구역에서 중복 탐지를 지웁니다
(다른 사진에서 온 박스끼리 IoU > 0.5 면 같은 잎으로 보고 신뢰도 높은 쪽만 남김).

잎이 움직여도 안전하고, 특징점 매칭도 OpenCV 도 필요 없습니다.
변환 행렬은 **순수 파이썬 가우스 소거법**으로 풉니다 (의존성 추가 없음).

> 모서리 네 점이 일직선이거나 겹치면 변환을 만들 수 없어 400 으로 거부합니다.

#### 묶는 방법: 화분 + 거리 + 생김새
세 가지 신호를 함께 씁니다. 화분이 잡히면 화분 기준, 아니면 거리 기준으로 가되
**양쪽 다 '생김새'로 교정**합니다.

| 상황 | 방식 |
|---|---|
| 화분이 잡힘 | 화분 안 잎은 그 화분으로 확정 → 화분 밖으로 뻗은 잎은 **가까움 x 닮은정도**로 배정 |
| 화분이 없음 | 가까운 잎끼리 잇되 **안 닮았으면 잇지 않고**, 확실히 닮았으면 더 멀리까지 이어 줌 |

떠돌이 잎 배정에 **곱**을 쓰는 게 중요합니다. 더하기로 하면 "아주 가깝다"가
"전혀 안 닮았다"를 덮어써서, 멀리 뻗은 잎이 옆 화분에 붙어 버려요.
곱이면 둘 다 맞아야 이깁니다 (테스트로 고정: 4배 더 가까운 화분을 제치고
생김새가 같은 화분으로 갑니다).

#### 🪴 화분 자리를 미리 지정하기 (라벨링 없이)
`pot` 클래스를 라벨링하는 대신, **화분 위치를 한 번만 찍어 두면** 됩니다.
화분은 안 움직이니 이후 스캔에서 계속 재사용돼요.

```
🪴 화분 자리 지정  →  사진 1장 선택
   → 선반 네 모서리 클릭 (원근 보정용)
   → 화분 중심을 하나씩 클릭 (빈 화분도 미리 찍어 두면 나중에 심었을 때 바로 잡힘)
   → 저장 (서버가 원근 보정해서 선반 좌표로 변환)
```

**부수 효과가 더 큽니다.** 화분마다 자리(슬롯)가 고정되므로
매번 스캔해도 **"이 화분 = 항상 같은 식물"** 이 보장됩니다.
잎이 흔들리거나 카메라 각도가 달라져도 개체가 섞이지 않고, 붙여 둔 이름도 유지돼요.
(테스트로 고정: 잎을 ±45px 흔들어도 자리가 그대로입니다.)

우선순위는 **모델이 잡은 화분 → 지정해 둔 자리 → 거리+생김새** 입니다.
나중에 `pot` 클래스를 라벨링하면 지정값 없이도 자동으로 그쪽을 씁니다.

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/pots` | 지정된 화분 자리 |
| POST | `/api/pots` | `points`(정규좌표) 또는 `points_px`+`corners`(사진 픽셀) |
| DELETE | `/api/pots` | 지정 해제 |

#### 화분(pot) 클래스를 라벨링하면
생김새 교정을 얹어도 화분 신호가 있는 쪽이 정확합니다.

거리 기준이 약한 건 알로카시아의 생김새 때문입니다. 잎이 잎자루로 사방으로 뻗어서
**이웃 식물의 잎이 같은 식물의 잎보다 더 가까운** 상황이 흔해요.
실제 배치로 재보면 같은 식물 안 두 잎이 510px 떨어져 있는데
이웃 식물과 맞닿은 잎은 92px 로, **5배 이상 가깝습니다.**
이러면 임계값을 아무리 조정해도 갈라지지 않습니다 (테스트로 고정해 뒀어요).

그래서 로보플로우 모델에 `pot` 클래스를 추가해 라벨링하시는 걸 권합니다.
화분은 서로 겹치지 않고 **1화분 = 1식물**이라 신호가 깔끔합니다.
`object` / `pot` 처럼 잎이 아닌 클래스는 잎 개수에서 자동으로 빠집니다.

거리 기준의 민감도는 `GROUP_GAP` 로 조절합니다 (기본 `0.6`, 클수록 잘 뭉침).

#### 🎨 모양 그룹 — 비슷하게 생긴 개체끼리 묶기
품종마다 잎 모양·무늬·색이 뚜렷이 달라서, 이걸로 **같은 품종끼리 A / B / C 딱지**를 붙입니다.
떨어진 자리에 있어도 닮았으면 같은 딱지를 받아요 (리스트의 색 배지 · 모달의 칩으로 표시).

**외부 API 가 필요 없습니다.** 박스의 긴변/짧은변 비율·크기와,
잎 가운데를 잘라 낸 색(HSV 평균)만으로 로컬에서 계산합니다. 무료이고 즉시 끝납니다.

민감도는 `SHAPE_SIM` 으로 조절합니다 (기본 `0.55`, 낮출수록 잘 뭉침).

> 한계: 모양 그룹은 **품종**을 나눌 뿐 품종 **이름**은 모릅니다.
> 같은 품종을 두 화분에 키우면 둘 다 같은 딱지를 받는 게 정상이에요.
> 이름까지 자동으로 붙이고 싶다면 그때는 외부 API(Gemini 등)가 쓸모 있습니다.

### 🗺️ 자리(슬롯) 시스템
사진만으로는 "무슨 식물인지" 구분할 수 없기 때문에, **자리로 개체를 식별**합니다.
온실 60 x 40 cm 를 **5줄 x 10칸 = 50자리** 로 나눠 `A1`~`E10` 라벨을 붙였어요 (한 칸 6 x 8 cm).

- 자리 지도에서 **빈자리 탭** → 그 자리가 자동 선택되고 이름 입력으로 이동
- 자리 지도에서 **찬 자리 탭** → 그 식물 상세 모달
- 식물 라벨은 3D 에서도 `A1 · 프라이덱` 형태로 표시

### 🎨 3D 표현 규칙
| 요소 | 색/크기 | 근거 |
|---|---|---|
| 화분 | 흰색 | 고정 |
| 새순(Shoot) | 연두 `#a4e05a` | 모델2 `shoot_count` |
| 성엽(Mature) | 녹색 `#35913c` | 모델2 `mature_count` |
| 노엽(Old) | 노랑 `#e0cf4a` | 모델2 `old_count` |
| 식물 크기 | 소엽 1.3 / 중엽 1.85 / 대엽 2.5 | 모델1 `top_leaf_size` |

화분 방향은 모달의 **🧭 슬라이더**로 0~359° 조절되며 서버에 저장됩니다.

## 분석 엔진 (자동 선택)
| 우선순위 | 조건 | 방식 |
|---|---|---|
| 1 | `ROBOFLOW_API_KEY` + 워크플로 지정 | **로보플로우 워크플로** |
| 2 | `ROBOFLOW_API_KEY` 만 | 로보플로우 모델(YOLO) |
| 3 | `.pt` 파일 있음 | 로컬 ultralytics |
| 4 | 아무것도 없음 | 데모(모델 없이 체험) |

현재 어떤 엔진이 도는지는 화면 왼쪽 위 **`분석 엔진:`** 에 표시됩니다.

### 로보플로우로 실제 분석
```bash
ROBOFLOW_API_KEY="개인키" ROBOFLOW_MODEL_ID="find-leaf-and-object/1" python3 -m uvicorn main:app --reload
```
> **Private API Key** 사용 (공개키는 막힘). Windows PowerShell 은 `$env:ROBOFLOW_API_KEY="..."; ...`

### 모델 2개 연동 (키 하나로)
로보플로우 키 1개로 **모델 두 개**를 함께 씁니다. 각각 다른 영역에 반영돼요:

| 모델 | 환경변수 | 반영 위치 |
|---|---|---|
| **모델1** 맨 위 잎(광합성) | `ROBOFLOW_MODEL_TOP` | **3D 온실** (식물 크기·강조 잎) |
| **모델2** 새순/성숙/노령 | `ROBOFLOW_MODEL_STAGE` | **개체 특징 모달** (단계별 개수) |

```bash
ROBOFLOW_API_KEY="개인키" \
ROBOFLOW_MODEL_TOP="top-leaf-model/1" \
ROBOFLOW_MODEL_STAGE="leaf-stage-model/1" \
python3 -m uvicorn main:app --reload
```
> 두 모델을 **다르게** 지정하면 사진 1장당 추론이 2번 돌아 크레딧도 2배예요.
> 같게 두거나 하나만 지정하면 1번만 호출(재사용)해서 절약합니다.

### 🔗 로보플로우 워크플로 연동
로보플로우에서 만든 **워크플로(Workflow)** 를 통째로 호출할 수도 있어요.
모델 여러 개·전처리·필터를 로보플로우 쪽에서 조립해 두고, 이 앱은 결과만 받아 씁니다.

```bash
ROBOFLOW_API_KEY="개인키" \
ROBOFLOW_WORKSPACE="s-workspace-br86f" \
ROBOFLOW_WORKFLOW_ID="find-old-leaf-and-others" \
python3 -m uvicorn main:app --reload
```

| 환경변수 | 설명 |
|---|---|
| `ROBOFLOW_WORKSPACE` | 워크스페이스 이름 |
| `ROBOFLOW_WORKFLOW_ID` | 워크플로 ID |
| `ROBOFLOW_WORKFLOW_URL` | (선택) 전체 URL 직접 지정 — 위 두 개 대신 |
| `ROBOFLOW_WORKFLOW_IMAGE_INPUT` | (선택) 워크플로 이미지 입력 이름, 기본 `image` |

동작 방식:
- 호출 경로는 `/infer/workflows/{워크스페이스}/{워크플로}` 를 먼저 시도하고,
  404 면 `/{워크스페이스}/workflows/{워크플로}` 형식으로 한 번 더 시도합니다.
- 워크플로마다 **출력 블록 이름이 달라서** 응답 구조를 고정할 수 없어요.
  그래서 응답 전체를 훑어 박스 형태의 `predictions` 를 모두 찾아 씁니다 (중복은 1회만 계산).
- 워크플로에 **리사이즈**가 들어 있으면 좌표계가 원본과 달라지므로,
  응답에 이미지 크기가 실려 있으면 그 크기를 기준으로 잎 비율을 계산합니다.
- 워크플로는 `confidence` 파라미터를 안 받는 경우가 있어 **결과를 받은 뒤 앱에서 걸러 냅니다**
  (`CONFIDENCE`, 기본 25%).

> 워크플로 모드에서는 사진 1장당 **호출 1번**이고, 그 결과를 3D(모델1 역할)와
> 모달(모델2 역할)에 함께 씁니다. 단계 구분은 클래스 이름으로 하므로
> 워크플로가 `shoot` / `mature leaf` / `old leaf` 계열 이름을 내보내면 색이 바로 반영돼요.

#### 테스트
```bash
python3 test_workflow.py      # 워크플로 응답 파싱 (네트워크 불필요)
python3 test_grouping.py      # 잎 → 식물 그룹화 · 농장 스캔 (네트워크 불필요)
python3 test_perspective.py   # 원근 보정 · 여러 장 합치기 (네트워크 불필요)
python3 test_pots.py          # 미리 지정한 화분 자리 (네트워크 불필요)
python3 test_edit.py          # 직접 수정 · 스캔 모드 (네트워크 불필요)
```

## API
| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/api/scan` | `file`(농장 전체 탑뷰) + `mode`(keep/update/replace) |
| POST | `/api/scan-multi` | `files` + (`corners`+`regions` 또는 `pot_refs`) → 원근 보정 후 합쳐서 등록 |
| POST | `/api/plants` | `name`+`file`+`pos` → 분석 후 식물 추가 |
| GET | `/api/plants` | 전체 목록 (+ 사용 중인 `engine`) |
| GET | `/api/slots` | 자리 50개 목록 + 점유 여부 |
| PATCH | `/api/plants/{id}` | `name` / `rot` / `size_class` / `shoot_count` · `mature_count` · `old_count` |
| POST | `/api/plants/{id}/reanalyze` | `file` → 새 사진으로 갱신 |
| DELETE | `/api/plants/{id}` | 제거 |

분석 결과 필드:

| 필드 | 출처 | 쓰이는 곳 |
|---|---|---|
| `top_leaf_size` (소엽/중엽/대엽/없음), `top_leaf_pct` | 모델1 | 3D 크기 · 모달 |
| `shoot_count`, `mature_count`, `old_count` | 모델2 | 3D 잎 색 · 모달 |
| `leaf_count`, `overlap_count`, `overlap_density`(%) | 모델2 | 모달 |
| `size_class` (대/중/소품) | 모델2 | 리스트 · 모달 |
| `shape_group` (A/B/C…), `shape_group_size` | 생김새 | 리스트 배지 · 모달 칩 |
| `manual`, `leaf_log`, `new_leaves` | 직접 수정 · keep 모드 | 모달 칩 · 스캔 결과 |
| `pos`, `x`, `z`, `rot` | 자리 시스템 | 3D 배치 |

> 식물 상태는 **메모리에만** 저장됩니다. 서버를 재시작하면 초기화돼요.
